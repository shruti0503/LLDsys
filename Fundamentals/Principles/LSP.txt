        cout<<"i am  a sparrow andi can fly<<endl;

    void fly() override {
        throw runtime_error("I cannot fly!");
    }

    bird->fly();
}

    Bird* sparrow= new Sparrow();

with LSP

Make a class bird do not impliment the method in this itself , make a general method (virtual function) that 
is later implimented in the derived classes.

In the class FlyingBird that extends from the class Bird make a virtual function here "fly" 
In the class NonFlyingBird that extends from the class Bird-> virtaual func -> walk
class->  Sparrow that is dervied from -> FlyingBird -> impliments fly() override
class->Pengin -> derived from -> NonFlyingBird -> impliments fly() override


class Bird(){

    void virtaual move();
    virtaual ~Bird(){};

};

class FlyingBird: public Bird{

    virtual void Fly()=0;
    void move() override{
       Fly();
    }

};

class Sparrow: pubic FlyingBird{
    void fly() override{
        cout<<" i can fly ehehe"<<endl;
    }

}

class NonFlyingBird: Bird{
    void virtual Walk()=0;
    void move() override{
       Walk();
    }

}

class Pengin: pubic NonFlyingBird{
    void walk() override{
        cout<<"I am penguin and i walk , huh !"<<endl;
    }

}
separate flying birds and non-flying birds into their respective hierarchies. 
Penguin behaves correctly without pretending to have abilities it doesn't have.


Real-Life Use Case:
Payment Systems:

A CreditCard and PayPal class should both behave like their parent PaymentMethod class,
without introducing unexpected behavior (e.g., a BitcoinPayment subclass that suddenly asks for unrelated setup).
Shapes Example:

A Rectangle class has width and height.
A Square is a subclass but can violate LSP because changing one dimension of a square must also change the other. 
This is better solved by avoiding inheritance here.
